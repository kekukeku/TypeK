# TypeK UI 刷新設計提案：兩套視覺與交互方向評估報告

> **專案背景**：TypeK（前身為 SayIt）是一款以 macOS 優先的桌面語音轉文字與 AI 整理應用（Tauri v2 + Vue 3 + shadcn-vue new-york + Tailwind 語意變數）。本報告為負責人 Kevin 提供兩套視覺與交互重構方向（**提案 A：Native Air** 與 **提案 B：Editorial Studio**），提供完整設計哲學、CSS Token 對照表、畫面改動細節、HUD 狀態、實作風險與評選建議。

---

## 提案 A：Native Air（原生質樸 · 幽微工藝）

### 1. 設計理念
將 TypeK 定位為如 macOS 系統功能般無縫、低調且值得信賴的「底層語音基石」。完全遵循 Apple macOS 人機界面指南（HIG），介面主動退居背景，以黑、白、微冷灰的嚴謹秩序呈現資訊，消除一切浮誇雜訊，讓使用者的注意力全然集中於文字產出。

### 3. 字體與間距
- **字體層級（Font Stack）**：優先呼叫系統字體 `-apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display", "PingFang TC", "Noto Sans TC", sans-serif`；代碼與計時器嚴格採用 `SF Mono, ui-monospace, Menlo, monospace`，並全面啟用 `font-variant-numeric: tabular-nums` 防止數字跳動。
- **字級階梯**：視窗標題 12px、次要說明 11px、本文 13px、卡片標題 13px / 14px、數據統計 22px（粗體緊湊）。
- **間距規範**：卡片 Padding 為 14px / 16px，組件間隔統一為 8px / 12px / 16px，資訊密度緊湊，大幅減少滑動需求。

### 4. 每個畫面改動細節
- **主視窗外殼與側邊欄**：
  - 頂部使用 38px macOS 原生 Titlebar 樣式，保留左側三色控制圓點與中央「TypeK」標記。
  - 側邊欄寬度收縮至 210px，採用系統微灰底色，讓視覺主體自然落在內容區。Logo 標章採純黑白反轉方塊，點綴「言」字印記。
- **儀表板（Dashboard）**：
  - 6 張統計卡片排版緊湊，數據字體增大至 22px，並標註清晰的單位「分」、「秒」、「字」、「次」。
  - 今日額度卡片結合 5px 線性感進度條與「Groq Whisper: 1,560 / 2,000 次」文字說明。
  - 7 日使用趨勢圖採簡練單色（系統藍）長條柱狀圖，搭配底部清晰日期標籤。
  - 最近轉錄項目採用微邊框條列，右側具備翡翠綠「AI 已整理」簡約徽章。
- **偏好設定頁（Settings）**：
  - AI 服務平臺選擇採用 4 格橫向卡片（Groq / OpenAI / Anthropic / Gemini），選中時以系統藍邊框與淡底色高亮。
  - 快捷鍵設定卡片區分「簡易預設」與「自訂錄製」，直覺下拉選取 Fn / Option / Command。
  - 「上下文感知」開關採用標準 macOS 20px 緊緻 Switch，下方附帶圓形資訊圖標與本地隱私承諾摘要。

### 5. HUD 狀態設計（Notch HUD）
Notch HUD 高度固定 38px，寬度約 360px，緊貼螢幕硬體鏡頭缺口：
- **錄音中**：6 根純白等寬音量條，動態起伏細緻自然；右側顯示等寬計時器（`00:14`）與「標準整理」微型標籤。
- **整理中**：4 顆微光圓點平滑滑動呼吸脈衝（Sliding Dots），右側呈現文字「AI 整理潤飾中...」，清晰提示非同步背景作業。
- **已貼上**：左側翡翠綠圓形打勾符號 + 白色文字「已自動貼上」，右側標記「耗時 0.8s」，雙重回饋確認文字已輸入。
- **錯誤**：琥珀橘警示符號 +「連線逾時，請檢查 API Key」文字 + 右側「重試 ↺」微型按鈕，配合溫和橫向抖動動效。

### 6. 實作工作量與風險
- **實作工作量**：**S（Small，極低）**。
- **技術風險**：風險趨近於零。百分之百對應現有 shadcn-vue 元件預設結構，僅需更新 `src/style.css` 的變數色碼與 `--radius: 0.5rem`，不需修改任何元件的 DOM 結構。
- **適合使用者**：追求極簡冷靜、偏好標準 Apple 系統工具風格、重視高工作效率與高資訊密度的專業開發者與工程師。

### 5. HUD 狀態設計（Notch HUD）
Notch HUD 採 42px 雕塑感膠囊，四周自帶微弱的琥珀環境光暈（Amber Aura）：
- **錄音中**：6 根漸變金黃赤陶波形條，伴隨動態頻譜起伏與立體光暈；右側顯示「✨ 語境感知」圓角膠囊與 `00:14` 計時器。
- **整理中**：雙環金色跳動光點交替呼吸放大，右側呈現知性文字「AI 正在雕琢修辭...」，營造文字精緻潤色中的期待感。
- **已貼上**：翡翠青瓷綠印章確認動效（綠色雙環印章戳印），顯示「文字已精準貼上」與「0.8s 提煉」勳章。
- **錯誤**：暖橘警示盾牌符號 +「API 金鑰無回應」文字 + 實體感「重試提煉 ↺」膠囊按鈕。

### 6. 實作工作量與風險
- **實作工作量**：**M（Medium，中等）**。
- **技術風險**：主要在於需微調部分 shadcn-vue 元件的自訂 class（例如：增加按鈕全圓角 `rounded-full` 樣式、調整 Switch 尺寸與漸變色彩），但仍然完全受限於現有 CSS 變數系統，不破壞底層架構。
- **適合使用者**：作家、內容創作者、高階經理人、重視軟體設計品味與情感連結、偏好如 Linear 或 Raycast Pro 般具備強烈品牌性格的使用者。

## 小 A（Antigravity）的審查與推薦

身為峨嵋派三師姊，從程式架構與產品心理學兩個層面，我向 Kevin 給出明確的建議：

> **小 A 核心推薦：直上【提案 B：Editorial Studio（編選工坊）】**。

### 推薦理由：
1. **擺脫 AI 語音工具的「冷酷技術感」**：
   目前市場上多數語音輸入軟體（如 Superwhisper、Wispr Flow）多走偏冷的深灰或無聊的黑白風，使用者容易覺得這只是一個「錄音驅動程式」。TypeK 剛由 SayIt 改名，正是建立品牌視覺護城河的絕佳契機！提案 B 導入暖琥珀赤陶色（Terracotta Amber）與溫暖紙質象牙底，賦予口述輸入一種「我在寫作、我在雕琢文字」的尊榮感。
2. **HUD 靈動島（Notch）的極致存在感**：
   在實際使用時，使用者盯著螢幕頂部瀏海的時間遠多於看儀表板主視窗。提案 B 的琥珀金聲波與青瓷綠戳印，在黑色瀏海上具有絕佳的視覺能見度與無障礙鑑別度，既不刺眼，又充滿能量。
3. **實作負擔完全可控**：
   雖然提案 B 風格濃烈，但它依然 100% 遵守 shadcn-vue 規範，核心變更點依然是 `src/style.css` 的變數覆寫與少量微調，完全符合我們「偷懶資深工程師（Ponytail）」最小有效變更原則。

如果 Kevin 偏好極致安靜、希望 App 完全融入 macOS 系統偏好設定裡不被察覺，則**提案 A（Native Air）**是無可挑剔的穩健解答；但若希望 TypeK 成為一款讓人愛不釋手、打開就想口述寫作的專業精品，**提案 B** 絕對是唯一答案！
